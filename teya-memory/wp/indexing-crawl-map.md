# Карта обхода и индексации — Дед Мороз и Снегурочка, Нижний Новгород

Дата: 28 октября 2026.  
Тема: `dedmoroz-nn`. Язык: `ru-RU`.  
Режим: план локальной темы. Файлы `robots.txt`, `sitemap.xml` и `llms.txt` в этой волне не публикуются.

Источники: `teya-memory/site.inv`, `teya-memory/wp/aurora-team-blueprint.md`, `teya-memory/research/site-research-dossier.md`, `teya-memory/semantic-core/dedmoroz-nn-2026-10-28/06-url-map.csv`, `07-content-briefs.md`, `11-blog-topics.md`.

## Статус


Единственный допустимый canonical host — значение `project.public_site_url` из `site.inv`. Сейчас поле пустое. Пока оно пустое, хост не назначается: ни в `Host`, ни в `Sitemap:`, ни в canonical, ни в `loc` sitemap, ни в `llms.txt`.

Публичного сайта нет. Домен не куплен. Имя `dedmoroz.ru` в dossier названо как некупленный план. Подставлять его в robots, sitemap, canonical, schema и видимый HTML нельзя. Технический хост локальной сборки, стенд хостинга и `localhost` тоже нельзя записывать как публичный адрес.

Проверка «`/sitemap.xml` отдаёт 200 и XML» в этой волне не выполняется: хоста нет. Это не пройденная проверка и не ответ 500. Её делает следующий проход после появления `public_site_url`.

## Что индексировать в этой сборке

Коммерческие страницы и оболочка блога. Все пути со слэшем на конце, как `permalink_structure = /%postname%/`.

| Путь | Роль | robots | В sitemap этой сборки |
|---|---|---|---|
| `/` | главная, корпоратив | `index, follow` после появления хоста | да |
| `/ded-moroz-na-dom/` | семья | `index, follow` | да |
| `/ded-moroz-v-detskij-sad/` | сад | `index, follow` | да |
| `/ded-moroz-v-restoran/` | ресторан и кафе | `index, follow` | да |
| `/kontakty/` | контакты и форма | `index, follow` | да |
| `/blog/` | архив тем, `home.php` | `index, follow` | да |

Рядом в sitemap, не как шестая услуга, две юридические страницы темы. Они нужны до формы и в blueprint §20 стоят в том же XML, что пять страниц и архив.

| Путь | Роль | robots | В sitemap |
|---|---|---|---|
| `/politika-konfidencialnosti/` | политика ПДн | `index, follow` | да |
| `/politika-cookies/` | политика cookie | `index, follow` | да |

Мета для этих восьми путей, когда сайт станет публичным:

`index, follow, max-snippet:-1, max-image-preview:large, max-video-preview:-1`

До публичного хоста эти директивы не выкладываются на живой домен. Локальная тема не должна утверждать, что сайт уже открыт для поиска.

`lastmod` для восьми путей, когда XML начнут отдавать: `2026-10-28`. Это дата брифа, dossier и карты ядра, не дата HTTP-запроса. Позже `lastmod` меняется только если изменился текст страницы в теме. `changefreq` и `priority` не ставить: приоритет обхода задаёт карта, не выдуманный вес.

BT03, BT04 и BT06 не ведут на `single.php`. BT01, BT02 и BT05 получают permalink только после PASS. До этого все шесть карточек на `/blog/` и на главной — видимый H1 без href. Schema `Article` на карточки не ставить. `llms-full.txt` с телами статей пишет Excalibur, не эта волна.

Служебные адреса в sitemap не попадают никогда:

- `/wp-admin/`, `/wp-login.php`, `/wp-json/` и прочие REST-маршруты;
- поиск `/?s=` и `/search/`;
- 404;
- отдельный URL успеха формы, если его когда-нибудь заведут;
- вложения, авторы, метки, рубрики, фиды, `embed`, пагинация `/blog/page/2/` и дальше;
- черновики и незарегистрированные слаги AURA.

## Canonical

Для каждого indexable URL — один self-referencing canonical на тот же путь.

Правило сборки, пока `public_site_url` пуст:

- не печатать `<link rel="canonical">` с абсолютным хостом;
- не брать хост из `home_url()`, `siteurl` или адреса локального WordPress;
- не собирать canonical из `dedmoroz.ru`.

Когда поле будет заполнено, canonical становится абсолютным и совпадает с `loc` в sitemap: схема и хост только из `public_site_url`, путь со слэшем, без параметров, без `www`, если его нет в поле. Дубль `rel_canonical` WordPress снять, если тема печатает свой canonical.

Страницы с `noindex` в sitemap не включать. Canonical 404 и поиска не сводить на главную.

## noindex, follow

| Адрес | Мета | В sitemap |
|---|---|---|
| поиск, `/?s=`, `/search/` | `noindex, follow` | нет |
| `404.php` | `noindex, follow` плюс `X-Robots-Tag: noindex, follow` | нет |
| успех формы отдельным URL | `noindex, follow` | нет |
| `/wp-admin/`, REST, логин | не индекс; в robots закрыт обход админки | нет |
| архив автора, метки, рубрики, вложения | `noindex, follow`, термины без своих посадочных не заводить | нет |
| `/blog/page/2/` и дальше | `noindex, follow` | нет |

Успех формы в этой сборке — текст на том же URL, не отдельная страница. Пути `/spasibo/`, `/thank-you/`, `/zayavka/` не создавать.

Восемь indexable путей этой сборки директиву `noindex` не получают.

## robots.txt — план, без публикации

Файл на хост не выкладывать, пока нет `public_site_url`. В теме можно хранить политику ниже, но строки `Host:` и `Sitemap:` не писать. Пометка плана: `pending_public_host`.

Не блокировать CSS, JS, изображения, шрифты и каталоги, где они лежат: `/wp-content/` и `/wp-includes/` в `Disallow` не ставить. Не блокировать Googlebot, YandexBot, Bingbot и разрешённых AI-краулеров.

Поиск в `Disallow` не закрывать: иначе робот не увидит `noindex`. Поиск остаётся доступным для обхода и закрыт мета-тегом. Админку и REST закрыть: это служебные URL, не документы сайта.

```text
User-agent: *
Allow: /
Allow: /wp-admin/admin-ajax.php
Allow: /wp-content/
Allow: /wp-includes/
Disallow: /wp-admin/
Disallow: /wp-login.php
Disallow: /wp-json/

User-agent: Googlebot
Allow: /

User-agent: YandexBot
Allow: /

User-agent: Bingbot
Allow: /

User-agent: GPTBot
Allow: /

User-agent: OAI-SearchBot
Allow: /

User-agent: ChatGPT-User
Allow: /

User-agent: ClaudeBot
Allow: /

User-agent: PerplexityBot
Allow: /

User-agent: Google-Extended
Allow: /

User-agent: CCBot
Allow: /
```

После появления `public_site_url` в конец файла добавляются ровно две строки, хост без выдумки:

```text
Host: {public_site_url без схемы}
Sitemap: {public_site_url}/sitemap.xml
```

Пока поля нет, эти две строки отсутствуют. Пустой `Host:` и Sitemap на локальный или технический адрес — тот же блокер, что и чужой хост.

Коды верификации Яндекса и Google в `site.inv` пустые. Мета-теги верификации не выдумывать.

## sitemap.xml — руководство

Отдавать один `urlset` по `http://www.sitemaps.org/schemas/sitemap/0.9`. В `loc` только канонические indexable URL на публичном хосте. Пока хоста нет, XML не публиковать и не отвечать им с технического домена.

Состав, когда хост появится, ровно эти восемь путей:

1. `/`
2. `/ded-moroz-na-dom/`
3. `/ded-moroz-v-detskij-sad/`
4. `/ded-moroz-v-restoran/`
5. `/kontakty/`
6. `/blog/`
7. `/politika-konfidencialnosti/`
8. `/politika-cookies/`

У каждого узла: `loc` и `lastmod`. `lastmod` в формате `YYYY-MM-DD`.

Исключить: школа, четыре гео, BT01–BT06, админка, REST, поиск, 404, thank-you, авторы, рубрики, метки, вложения, фиды, пагинация блога, слаги AURA `/korporativ/`, `/na-dom/`, `/sad-i-shkola/`, `/zayavka/`.

Ответ `/sitemap.xml` на публичном хосте: HTTP 200 и XML. Ответ 500, HTML-заглушка или sitemap с техническим хостом — блокер релиза. В этой волне проверка пропускается, причина: `public_site_url missing`.

## Пагинация блога

В этой волне записей нет. `/blog/` — одна страница архива с шестью H1. Второй страницы нет, и ссылку «страница 2» не рисовать.

Когда появятся записи:

- в sitemap только `/blog/`;
- `/blog/page/2/` и дальше: `noindex, follow`, self-canonical на свой номер, в sitemap не включать;
- если все записи умещаются на первой странице, маршрут `/blog/page/2/` не отдавать как 200;
- `posts_per_page` не плодить пустые страницы ради обхода.

## 404 и soft-404

Настоящее отсутствие страницы:

- HTTP 404, шаблон `404.php`, мета `noindex, follow`;
- не HTTP 200 с текстом «страница не найдена»;
- не редирект всего неизвестного на главную;
- не подмена школы, гео или статьи без тела тонким лендингом.

К этому относятся незарегистрированные пути школы, четырёх гео, BT03, BT04, BT06 и любой слаг статьи до PASS.

Мягкий 404, который нельзя допустить:

- пустой `single.php` с кодом 200;
- черновик, открытый как публичная запись;
- поиск без результатов, который выглядит как главная и отдаёт 200 без `noindex`;
- архив рубрики из одного города, собранный автоматически.

Пустой поиск остаётся страницей поиска: код ответа поиска WordPress, `noindex, follow`, не главная.

## Редиректы

`old_url_map_path` в `site.inv` пуст. Публичного старого сайта нет. Миграционных пар «старый URL → новый URL» в источниках нет. Редиректы не выдумывать.

| Источник | Действие |
|---|---|
| карта старых URL | данных нет, правил 301 нет |
| конкурентные домены из dossier | не наши адреса, не редиректить |
| `/korporativ/` | в публичный обход не выходил; не регистрировать и не вести 301 на ресторан |
| `/na-dom/` | не регистрировать, не вести 301 на дом |
| `/sad-i-shkola/` | не регистрировать, не вести 301 на сад |
| `/zayavka/` | не регистрировать, не вести 301 на контакты |

Эти четыре слага AURA — внутренние имена макета. Если их запросят на будущем хосте, ответ 404, не переезд.

## Что нельзя закрыть статусом готовности

- `public_site_url` пуст;
- `Host` не равен публичному домену, потому что домена нет;
- `Sitemap:` не указывает на публичный домен, строку не пишем;
- `/sitemap.xml` не проверен ответом 200;
- canonical с хостом не печатать;
- школа, гео, статьи без тела и служебные URL в sitemap не входят.

Когда домен купят и поле заполнят, повторить карту: подставить один хост, опубликовать robots и sitemap, проверить 200 и XML, сверить canonical восьми путей. До этой правки индекс не считать открытым.
